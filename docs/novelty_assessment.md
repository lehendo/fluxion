# Fluxion — Novelty Assessment & Literature Review

**Date:** 2026-07-03 (surface-level pass), deep-verified 2026-07-03 same day (direct quotes pulled from primary sources for all 15 papers)
**Purpose:** Verify, before any paper planning proceeds, that Fluxion's core combination is not incremental and has not already been done. This supersedes the 2026-06-28 search recorded in project memory — the field has moved meaningfully in the days between searches, which is itself informative (see "Strategic implications" below).

**The claim being tested:** a model combining ALL FOUR of:
1. **OT-CFM** (Optimal Transport Conditional Flow Matching) specifically as the generative/training objective — not generic flow matching, not diffusion, not an SDE, not autoregressive LM fine-tuning.
2. Operating directly in the **frozen internal trunk latent representations** of a pretrained structure-prediction model (Chai-1's single/pair reps, analogous to AlphaFold's Evoformer reps) — not 3D coordinates, not a custom-trained autoencoder/VAE/GNN, not a discrete tokenizer.
3. A **DiT** (Peebles–Xie diffusion transformer, AdaLN-zero conditioning) architecture as the velocity network.
4. Generating **temporal MD trajectories** (a genuine time series with meaningful order), not a static i.i.d. conformational ensemble.

## Verdict

**Zero of the 15 closest papers found satisfy all four criteria**, verified by direct quotes pulled from primary sources (abstract + methods), not secondhand paraphrase. This was checked two ways: (1) a dedicated fetch of the April 2026 survey "Learning Structure, Energy, and Dynamics: A Survey of AI for Protein Dynamics" (arXiv:2604.25244), which explicitly concluded "DiT-style architectures appear absent from the protein dynamics literature surveyed" and found no method satisfying all four criteria; (2) a paper-by-paper deep read of all 15 closest competitors, each checked against all four criteria individually with quoted evidence.

**Three papers' primary sources were inaccessible** (bioRxiv blocked all fetch attempts with Cloudflare 403s: BioKinema, AlphaFold Latent Flooding, DynaFold). Their entries below rest on secondary sources (author posts, GitHub READMEs, independent surveys) and are flagged explicitly — treat as unverified, not cleared, until read directly (e.g. via institutional/authenticated bioRxiv access).

**The surrounding space is far more crowded than the 2026-06-28 search found, and moving fast.** At least 8 new directly-relevant papers surfaced between the 06-28 and 07-03 searches.

## Strategic implications for the project

1. **The architectural novelty claim survives full verification**, and is now confirmed with direct quotes rather than surface-level characterization. No paper combines OT-CFM + frozen trunk latents + DiT + temporal generation. The distinguishing axes: (a) frozen pretrained trunk latents (Chai-1/AF3-style) vs. everyone else's raw coordinates, custom autoencoders, or custom GNNs; (b) OT-CFM specifically vs. everyone else's diffusion, SDEs, stochastic interpolants, or generic flow matching; (c) DiT specifically vs. IPA/GRU/graph-networks/Evoformer-derived/MLP architectures; (d) genuine temporal trajectory generation vs. the many methods that only produce static i.i.d. ensembles.

2. **MDGen and ConfRover are the two closest competitors overall** — MDGen on architecture (SiT is explicitly DiT-derived) and temporal generation; ConfRover on the encoder→latent→temporal-module→decoder pipeline shape. Neither uses OT-CFM or a frozen structure-predictor trunk latent space in the sense Fluxion does.

3. **BioKinema and TEMPO have already solved, in their own architectures, almost exactly the problem our pilot just discovered** (thermal noise dominates short MD lags — TEMPO via explicit two-timescale modeling, BioKinema via continuous-time attention, per secondary sources). Good news: independently confirms our diagnostic finding was correct and physically grounded. Bad news: whatever fix we adopt (longer lag, explicit velocity conditioning, multi-scale) must be framed as *our* application of a known idea within a novel architecture, not claimed as a new insight.

4. **Three papers remain unverified from primary sources** (BioKinema, AFLF, DynaFold — all blocked by bioRxiv's Cloudflare protection across repeated attempts). None of the three, even under the most generous unverified reading, appears to satisfy all four criteria — but this should be closed out with authenticated access before a paper submission, not left as an open gap.

5. **BioEmu (Science) remains the benchmark to beat or match on standard metrics** (RMSF correlation, PCA/TICA projection overlap, free-energy landscape reproduction) whenever we get to evaluation — the field's current highest-profile result, trained at a scale (200+ ms aggregate MD) this project cannot realistically match. Several of the closest architectural competitors (ConfRover, MDGen, UniSim) instead targeted top ML conferences (NeurIPS/ICML) rather than Nature-family journals — a legitimate, arguably more realistic comparison class for a project at this scale.

## Addendum (2026-07-16): static-ensemble pivot — updated competitor set

**Why this addendum exists.** All diagnostics on the temporal (frame-to-frame) formulation came back negative (see project memory `project_fluxion_overview.md` for the full chain: static/linear/velocity/nonlinear probes all ~0% signal, real trained model never beat baseline). Fluxion pivoted to generating **static conformational ensembles** (noise → equilibrium-sample OT-CFM, no frame pairing) instead of temporal trajectories. This retires criterion 4 (temporal generation) as part of Fluxion's own claim — Fluxion is now in direct competition with the *static*-ensemble methods already in the table above (BioEmu, AlphaFlow/ESMFlow, P2DFlow), not primarily with the temporal-trajectory methods (ConfRover, MDGen, TEMPO, UniSim, MD-LLM-1) that were the closest comparators pre-pivot.

**Surviving novelty claim, restated for the static-ensemble framing:** OT-CFM (not diffusion, not a flow-matching-with-OT-path variant) operating **directly inside a frozen structure-prediction foundation model's internal trunk latents** (Chai-1 single+pair reps), denoised by a **DiT**. Checked against the existing table: BioEmu (diffusion, AF2-lineage latents, no DiT) and AlphaFlow/P2DFlow (flow matching, but 3D coordinates not latents, no DiT) already fail at least 2 of these 3 criteria each — this was true before the pivot and remains true after it. The new addition below is Mac-Diff, the field's newest entry (published NMI, Feb 2026) and the closest by task/benchmark/positioning.

**Verdict: Mac-Diff fails all 3 of Fluxion's surviving novelty criteria** (frozen structure-predictor latent space, OT-CFM, DiT) — on the representation-space axis specifically, it's positioned as the *opposite* design choice, not a variant. It is, however, now a **mandatory related-work citation**: same benchmark dataset family, same baseline (BioEmu), same "smaller academic lab" positioning narrative, same target-venue class (NMI). Treat this the way TEMPO/BioKinema were treated for the temporal formulation — a paper that solves an adjacent problem well and must be addressed directly in related work, not evidence the idea is already done.

**Practical implication for the venue question:** Mac-Diff's existence and acceptance at NMI is actually informative evidence *for* the venue fit (see `project_publication_strategy.md`) — it confirms NMI accepts single-academic-lab, ATLAS-benchmarked, BioEmu-compared, no-wet-lab-validation papers in this exact shape. It does not weaken Fluxion's own novelty claim, which rests on a different representation space, generative framework, and architecture.

## Addendum (2026-07-31): real-decode evaluation, diversity deficit, and the OT-coupling fix

**Why this addendum exists.** The static-ensemble model (2026-07-16 addendum) was trained and evaluated. The first evaluation pass used nearest-neighbor decoding (cheapest — reuse a real training frame's coordinates for whichever generated latent it's closest to), which has a "ceiling effect": it can only ever return structures the training set already contains, so it cannot detect mode-collapse or a diversity deficit in the generative model itself. Re-evaluating with the real Chai-1 diffusion decoder (`inference/visualize.py`'s `chai1_decode_to_cif`, substituting the generated single/pair representation for Chai-1's own trunk output and running its unmodified diffusion inference pipeline — validated against ground-truth coordinates for a known ATLAS frame, RMSD ≈ 0.79 Å) surfaced a genuine problem the NN decode had masked: suppressed conformational diversity relative to the real MD ensemble.

**Diagnostic chain.** Two sampling-time explanations were tested and ruled out before looking at training: (1) RK4 vs. Euler ODE integration gave identical results — not an integrator-quality artifact; (2) rescaling the noise magnitude at sampling time traded diversity for RMSF-correlation accuracy rather than fixing the underlying issue — not a clean recoverable-at-inference-time fix. The deficit was then confirmed to generalize (in a worse, different form) to a second, structurally more complex protein: uniform variance underestimation with strong RMSF shape correlation on the first (smaller) protein, vs. generated samples landing entirely outside the real ensemble's occupied conformational modes on the second (larger) one. Both signatures are consistent with the same underlying cause: mode-averaging in the training objective.

**Root cause.** The codebase named its training objective "OT-CFM" from early in the project, but `training/flow_matching.py` / `training/train_static.py` implemented plain conditional flow matching — `(z0, z1)` pairs matched by arbitrary batch index — never the actual minibatch optimal-transport coupling the name implies (Tong et al. 2023). Arbitrary pairing makes the MSE-optimal predictor the conditional expectation over every consistent-looking-but-unrelated `(z0, z1)` pair in a batch, which averages over genuinely contradictory targets when the underlying distribution is multimodal — exactly the failure signature observed.

**Fix.** `training/ot_coupling.py` implements the real minibatch OT coupling: exact Hungarian-algorithm linear assignment (padding-aware, since training batches mix proteins of different lengths) re-pairs each `z0` to its transport-optimal `z1` within the minibatch before the loss is computed. Unit-tested (8 dedicated tests, including a hand-computable-optimum case and a padding-awareness divergence case) and smoke-tested on real GPU/data before committing to a full retrain. A retrain with `--ot-coupling` enabled (writing to a fresh `checkpoints_static_otcfm/` path, not resumed from the pre-fix checkpoint — resuming would mix weights trained under the old, arbitrary pairing scheme into a supposedly clean comparison) is the actively evaluated model as of this writing.

**Implication for the novelty claims above:** none of this changes the four novelty criteria or the competitor table — OT coupling was always claimed as part of "OT-CFM"; this addendum documents that the claim is now actually true in the implementation, not merely in the name, and explains a real implementation gap that existed for most of the project's history. This is exactly the kind of thing a careful reviewer or reproduction attempt would have caught, so it needed fixing regardless of whether it explains the observed diversity deficit.

## What this doesn't resolve

This review confirms the *idea* is not already done, verified now with direct primary-source quotes rather than a surface-level pass. It does not resolve whether Fluxion, once reformulated to use a longer time lag or explicit temporal conditioning, will actually produce a working, competitive model — that's still the open question from the pilot, unchanged by this literature review, and the reason the full paper design doc is being held until we have that result (per plan: option 2). The static-ensemble pivot (2026-07-16 addendum) carries the same caveat, now sharpened by the 2026-07-31 addendum above: novelty of the *idea* is confirmed, but whether the OT-coupling retrain actually produces a competitive, non-mode-collapsed ensemble is still an open, unresolved question pending that retrain's completion and re-evaluation against the same real-Chai-1-decode pipeline that surfaced the original deficit — do not assume it's fixed until that evaluation is in.
