# Fluxion

Flow matching in the latent space of a frozen protein structure predictor, for modeling protein conformational dynamics.

Fluxion takes molecular dynamics (MD) trajectories, encodes every frame with the trunk of a pretrained structure-prediction model ([Chai-1](https://www.chaidiscovery.com/)), and trains a diffusion transformer with conditional flow matching directly on those latents. Generated latents can be decoded back to 3D structure with Chai-1's own diffusion module. The structure predictor is never fine-tuned.

## Overview

**Why latent space.** Structure predictors such as Chai-1 and AlphaFold compress a protein and its context into rich internal representations before any coordinates are produced. Modeling dynamics there, instead of in Cartesian coordinates or hand-built internal coordinates, inherits the predictor's learned notion of what a plausible protein looks like. Fluxion provides the pieces needed to test that idea end to end.

**The pieces.**

1. **Latent extraction.** Frames from MD trajectories (e.g. [ATLAS](https://www.dsimb.inserm.fr/ATLAS/)) are passed through Chai-1's trunk to obtain, per frame, a single representation of shape `[L, 384]` and a pair representation of shape `[L, L, 256]`. Latents are stored in sharded HDF5 files so that large trajectories can be processed in parallel.
2. **Generative model.** `FluxionDiT` is a diffusion transformer over the single representation, with the pair representation entering as a bias in self-attention and the flow time entering through adaptive layer norm.
3. **Training.** The model regresses the straight-line velocity between a source latent `z0` and a target latent `z1`, with `z_t = (1 - t) z0 + t z1`. Two pairings are supported:
   - *temporal*: `z0` and `z1` are frames of the same trajectory a fixed lag apart (the observed coupling);
   - *static ensemble*: `z0` is Gaussian noise and `z1` is an equilibrium frame, optionally re-paired within each minibatch by exact optimal transport.
4. **Sampling and decoding.** Latents are generated by integrating the learned velocity field (Euler, Heun, RK4, or an adaptive solver). A generated latent can be decoded to coordinates either by nearest-neighbor retrieval of a training frame or by running Chai-1's unmodified diffusion module on the generated representation.
5. **Evaluation.** Utilities compare generated ensembles with MD (pairwise RMSD distributions, RMSF profile correlation, PCA overlap), and compare frame-prediction models against zero-parameter references (predicting the current frame, predicting the per-position mean) at stated lags.

**Conventions worth knowing.**

- Chai-1 pads inputs to fixed bucket sizes, and the padded token positions are constants rather than signal. Fluxion derives a mask from the true sequence length and applies it in losses and metrics.
- Latents are normalized per channel with statistics computed from the training frames.
- Training checkpoints store optimizer, scheduler and all random-number-generator state, and are written atomically, so interrupted runs resume exactly.

## Installation

Requires Python 3.10 and a CUDA-capable GPU.

```bash
pip install -r requirements.txt
```

Dependencies are pinned to a set of versions known to work together (including a CUDA build of PyTorch and `chai-lab`). Chai-1 downloads its own weights on first use. Decoding with Chai-1's diffusion module is memory-hungry (roughly 40 GB of GPU memory); extraction, training and nearest-neighbor decoding need far less.

Run the test suite with:

```bash
pytest
```

## Usage

Each stage (latent extraction, normalization statistics, training, sampling, decoding, evaluation) is a command-line program; run any of them with `--help` for its options.
